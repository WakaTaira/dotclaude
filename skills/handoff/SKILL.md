# handoff

CLAUDE.local.md は毎セッションの冒頭に全文が読み込まれる。だからこれは日誌ではなく**引き継ぎ書**として扱う。次のセッションの自分が、この 1 枚だけで「どこまで済んでいて、次に何をするか」を決められる状態にする。読み込みのたびに全文がコンテキストを食うので、足すたびに畳む。続きは新しいセッションで行う前提とする。

## 場所

| 名前 | パス |
|---|---|
| 引き継ぎ書 | `git rev-parse --show-toplevel` の直下の `CLAUDE.local.md`。git 管理外のディレクトリなら作業ディレクトリ直下 |
| メモリ | システムプロンプトが示すメモリディレクトリ。示されていなければ、`ls ~/.claude/projects/` から作業ディレクトリの絶対パスに対応する名前（区切り記号を `-` に置き換えた形）を選び、その下の `memory/`（無ければ作る。MEMORY.md も同様） |
| 退避先 | メモリディレクトリの隣の `local-md-archive/`（無ければ `mkdir -p` で作る） |
| 過去の記録 | `~/.claude/session-data/` の中で、`**Project:**` 行が引き継ぎ書のディレクトリと一致し、引き継ぎ書の冒頭行にある圧縮日以降の日付のファイル（初回はすべて） |

メモリの 1 件は、frontmatter（`name`・`description`・`type`）付きの markdown 1 ファイルに 1 トピックとする。作ったら MEMORY.md に 1 行の索引を足す。MEMORY.md も毎セッション読み込まれるので、索引の行は短く書く。

## 引き継ぎ書の形

節は次の順に固定する。該当する中身が無い節は置かない。

| 節 | 入れるもの |
|---|---|
| 運用 | このプロジェクトでだけ通用する進め方の決めごと（CLAUDE.md に書いていないもの）。ユーザーが書いた決めごとは原文のまま写し、言い換えるときはユーザーに確かめる |
| 現状 | ブランチ・最新コミットやタグ・配備先の版・着手中の課題・課題管理に書いていない決定。いま真であることだけ |
| 次にやること | 番号付き、5 件まで、上から着手する順。各項目に、着手に要るパスやコマンドを添える |
| 環境 | ホスト・サービス・配備手順など、コードから読めない前提 |
| 罠 | 再発しうる失敗と、その回避策 |
| 履歴 | 区切り（リリース・フェーズ・大きな決定）ごとに 1 行、新しい順に 10 行まで |

上限は 60 行・10 KB、1 項目は 1〜3 行。日付は必ず絶対日付で書く（「昨日」「次回」は書かない）。

## 手順

1. **対象を確かめる。** 引き継ぎ書のパスを決め、git 管理下なら次の 2 つを確認する（git 管理外なら飛ばす）。`<root>` は `git rev-parse --show-toplevel` の出力。
   - `git -C <root> ls-files --error-unmatch CLAUDE.local.md` が失敗する（追跡されていない）
   - `git -C <root> check-ignore -q CLAUDE.local.md` が成功する（無視されている）

   どちらかが外れたら、何も書かずにユーザーへ伝え、`.gitignore` への追加か追跡の解除をするかを聞く。完了条件: 引き継ぎ書がコミットされない状態だと確認できている。

2. **材料を集める。** 次を読む。
   - 既存の CLAUDE.local.md（無ければ新規作成になる）
   - この会話で決まったこと、済んだこと、残ったこと
   - `git status`・`git log --oneline -15`・タグ・未マージのブランチ
   - 課題管理を使っているなら、開いている課題の一覧（GitHub なら `gh issue list`）
   - メモリの索引（MEMORY.md）と、関係しそうなメモリの本体
   - 過去の記録（「場所」の表を参照）

   完了条件: 「現状」に書く各項目に、裏付けが 1 つある。裏付けは、コマンドの出力・ファイル・この会話で見たツールの出力のどれか。手元で確かめられない事実（別ホストの状態など）は旧版から引き継ぎ、`（YYYY-MM-DD 時点）` を付ける。

3. **退避する。** 既存の CLAUDE.local.md が無ければ飛ばす。あれば書き換える前に、既存の CLAUDE.local.md を `local-md-archive/CLAUDE.local-YYYY-MM-DD.md` へコピーする（同じ名前があれば `-2` などの連番を付ける）。完了条件: `cmp -s` で元と一致する。

4. **仕分ける。** スクラッチパッドに仕分け表を作り、材料を 1 項目ずつ 1 行にして、次のどれかに振り分ける。

   | 行き先 | 条件 |
   |---|---|
   | 残す | いまも真で、次のセッションの判断に効く。短く言い直してよい。ただし「運用」の項目は原文のまま写す |
   | 履歴へ畳む | 済んだ区切り。経緯を捨てて 1 行にする。11 行目より古い行は、メモリの `<引き継ぎ書のあるディレクトリ名>-history` へ移す（作ったときは MEMORY.md に索引を足す） |
   | メモリへ移す | 要るが詳しすぎる（手順・実測値・罠の細部）。トピック 1 つにつきメモリ 1 件とし、既存のファイルで足りるならそれを更新する。引き継ぎ書にはそのメモリ名だけを書く |
   | 残りへ回す | 「次にやること」の 6 件目以降。「現状」に「残り:」として 1 行で並べ、課題管理があれば手順 7 で課題の候補として挙げる |
   | 消す | 解決済みで再発しない／git log・コード・README・CLAUDE.md・課題管理から読める／すでにメモリにある／もう誰も引かない値（古い版の sha、バックアップのファイル名など） |

   完了条件: 表の行が、旧版の全項目・この会話の決定・読んだ過去の記録をすべて覆い、どの行にも行き先が入っている。メモリへ書く内容に秘密（パスワード・トークン・鍵・vault の中身）が無い。

5. **書き直す。** 「引き継ぎ書の形」に沿って CLAUDE.local.md 全体を書き直し、表で「メモリへ移す」とした分はメモリに書く。冒頭行は `<!-- handoff: YYYY-MM-DD, archive: <退避先のパス> -->` の形で書く（退避先が無ければ `archive: none`。次回はこの日付以降の過去の記録だけを読む）。完了条件: `wc -lc CLAUDE.local.md` が上限に収まり、引き継ぎ書に秘密が無い。収まらなければ手順 4 に戻り、メモリへ移すか消す項目を増やす。「運用」だけで上限を圧迫するなら、どれをメモリへ移すかをユーザーに確かめる（勝手には移さない）。

6. **点検する。** 「次にやること」の 1 件目に、この 1 枚だけを読んで着手できることを確かめる。

7. **報告する。** ユーザーには次だけを伝える。
   - 旧版と新版の行数・容量
   - メモリへ移したもの（ファイル名）と、消した主なもの
   - 課題の候補（「残り:」の項目）。課題管理が公開されうるので、起こすのはユーザーが承認してからにし、本文は引き継ぎ書から写さず公開向けに書き直す
   - 退避先のパス
   - 「次にやること」の 1 件目

## 判断の基準

- **迷ったら消さずにメモリへ移す。** 引き継ぎ書から外しても、メモリと退避ファイルに残るので失われない。
- **会話の中だけの話は書かない。** 次のセッションの判断を変えない雑談や説明は、引き継ぎ書にもメモリにも入れない。
- **CLAUDE.md は触らない。** あちらはリポジトリに入る共有の指示書で、この手順の対象外とする。
